# 코덱스 지시서 — 제작허브 인덱스형 개편 (2026-07-30)

> 발신: 로부장 | 수신: 코덱스
> 문제: 현 제작허브.html은 156장면이 한 페이지 세로 나열이라 스크롤 지옥이다 (대표님 직접 반려).

## 0. 절대 규칙 — 수정 대상은 build_hub.py다
- ⛔ **제작허브.html을 직접 고치지 마라.** 그 파일은 `build_hub.py`가 생성한다. HTML만 고치면 다음 빌드에서 증발한다. **build_hub.py를 고치고 `python3 build_hub.py`로 재생성**하라.
- ⛔ localStorage 키 `hub_status`와 장면 id 체계는 **한 글자도 바꾸지 마라** — 대표님 판정 기록이 거기 들어있다. 날리면 반려다.
- ⛔ 외부 라이브러리·서버 통신 금지. 단일 HTML 유지.
- 장면 데이터(scenes/*.json, 챕터별_프롬프트.html) 내용은 읽기만. 수정 금지.

## 1. 목표 화면 (인덱스형)
1. **첫 화면 = 갈래 인덱스만**: 갈래 칩(버튼) 그리드. 각 칩에 `갈래명 + 합격 n/전체 n` 뱃지. 진행 상태에 따라 칩 색 변화(0%=회색, 진행중=주황, 100% 합격=초록)
2. **칩 클릭 → 그 갈래의 장면만 표시** (다른 갈래는 렌더 안 함). 상단에 [← 인덱스로] [이전 갈래] [다음 갈래] 버튼
3. 장면 카드 동작은 현행 유지: 펼치기 → [복사] [생성완료] [합격] [불합격]
4. 전역 검색 유지: 검색어 입력 시 전 갈래에서 매칭 장면만 표시
5. 상단 고정 진행률 바(전체 합격/156) 유지
6. **모바일 390px 기준으로 설계** — 칩 그리드 2열, 버튼 터치 크기 44px 이상

## 2. 완료 판정 (관찰 가능)
1. `python3 build_hub.py` 재생성 성공 로그 원문
2. 스크린샷 2장: 데스크톱 인덱스 화면 + **390px** 갈래 상세 화면
3. 개편 전 판정 기록(hub_status)이 개편 후에도 그대로 표시됨을 확인하는 문장 + 근거(키·id 불변 diff)
4. "완료했습니다" 한 줄 보고는 미완료 처리

## 3. 금지
탭·통계 차트·다크모드 등 기능 추가 금지. 요청받은 인덱스 구조만.

## 개정 1 (2026-07-30) — 인덱스를 2단으로: 챕터 → 갈래 → 장면

1. 첫 화면 = **챕터 카드 9장** (다이어리 인덱스처럼). 각 카드에 챕터명 + 진도(합격 n/전체 n) + 진행바
2. 챕터→갈래 매핑은 `챕터배정_초안_v1.md`의 **트랙 A 9장** 그대로. build_hub.py 안에 CHAPTER_MAP dict로 넣어 라벨 교체가 한 줄이 되게 하라 (챕터명은 임시 — 대표님 확정 시 갈아끼움)
3. 챕터 카드 클릭 → 그 챕터의 갈래 칩들 → 갈래 클릭 → 장면. [← 뒤로] 항상 제공
4. 완성 12장면('챕터1-2 완성분' 그룹)은 별도 챕터 카드 "챕터 1–2 (완성)"으로 최상단 고정
5. 트랙 B(어근 챕터)는 **구현하지 마라** — 보류 딱지 붙은 안이다
6. 기존 규칙 전부 유지: build_hub.py만 수정, hub_status·장면 id 불변, 390px 기준, 외부 라이브러리 금지
7. **진도 표현 = 도장판** (대표님 지시 "채워지게, 차곡차곡"): 챕터 카드 안에 그 챕터 장면 수만큼 작은 칸 그리드를 깔고, 합격 장면 수만큼 칸이 채워진다 (빈 칸=연회색, 합격=진초록, 생성완료=연두, 불합격=붉은 점). 챕터 전체 합격 시 카드에 완성 표식(예: 금테). 퍼센트 숫자보다 칸이 메워지는 시각이 우선이다.
