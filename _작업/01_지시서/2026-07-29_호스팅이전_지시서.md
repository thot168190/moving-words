# 호스팅 이전 — GitHub Pages → Cloudflare Pages

> 로부장 | 발행 2026-07-28 · 시공 2026-07-29
> 사유: **GitHub Pages 약관이 상거래 사이트 운영을 금지한다.** 결제를 붙이기 전에 옮긴다.

---

## 0. 왜 클라우드플레어인가 (유료 검토 결과)

| | 월 비용 | 대역폭 | 상업적 사용 | 판정 |
|---|---|---|---|---|
| GitHub Pages (지금) | 0원 | 100GB 소프트 | **금지 조항 있음** | 떠나야 함 |
| **Cloudflare Pages** | **0원** | **무제한** | **허용** | **채택** |
| Netlify 무료 | 0원 | 100GB | 허용 | 지금과 같은 한계. 넘으면 정지 |
| Netlify Pro | 약 27,000원 | 1TB | 허용 | 지금 규모에 과지출 |

**돈을 쓸 곳은 호스팅이 아니라 영상 제작이다.**
영상이 288편으로 늘어 월 1TB를 넘기면 그때 **Bunny.net**(GB당 약 13원) 또는 **Cloudflare R2**(전송료 0원)로 영상만 분리한다. 지금은 아니다.

---

## 1. 이전 방식 — 빌드 방법을 바꾸지 않는다

지금은 `npx gh-pages -d dist-final` 이다.
이전 후에는 `npx wrangler pages deploy dist-final` 이다.

**그게 전부다.** 빌드 명령·폴더 구조·소스 코드는 한 줄도 바뀌지 않는다.
GitHub 저장소 연동(자동 빌드)은 **쓰지 않는다.** 지금 방식과 달라져서 사고가 난다.

---

## 2. 대표님이 먼저 알려주실 것 — 이것 없이는 못 움직인다

1. **`inkword.site` 를 어디서 구입하셨는지** (가비아 / 후이즈 / 카페24 / Namecheap / GoDaddy 등)
   - 클라우드플레어로 옮기려면 그곳에서 **네임서버**를 바꿔야 한다
2. 그 사이트 로그인 가능 여부

---

## 3. 순서

### 3-1. 로부장 — 사전 준비
- [ ] Cloudflare Pages 프로젝트 설정값 확정
- [ ] Firebase 승인된 도메인에 추가할 주소 목록 산출
- [ ] 되돌리기 절차 문서화 (아래 §6)

### 3-2. 대표님 — 계정 (10분)
- [ ] Cloudflare 가입 (`dash.cloudflare.com`, 무료, 카드 불필요)
- [ ] `inkword.site` 도메인 추가 → 클라우드플레어가 기존 DNS 레코드를 자동으로 읽어온다
- [ ] **읽어온 레코드 목록을 캡처해 로부장에게 전달** (지우면 안 되는 게 섞여 있다 — 메일 MX 등)
- [ ] 구입처에서 **네임서버를 클라우드플레어 것으로 변경**

### 3-3. 코다리 — 배포 (10분)
```bash
npm i -D wrangler
npx wrangler pages project create inkword --production-branch=main
npx wrangler pages deploy dist-final --project-name=inkword
```
- [ ] 나온 `*.pages.dev` 주소를 보고 **먼저 그 주소로 동작 확인** (도메인 연결 전)

### 3-4. 도메인 연결
- [ ] Cloudflare Pages → 프로젝트 → Custom domains → `inkword.site` 와 `www.inkword.site` 추가

### 3-5. 로부장 — 연결 후 필수 조치
- [ ] **Firebase 콘솔 → Authentication → 설정 → 승인된 도메인**에 `inkword.pages.dev` 추가
      (이거 안 하면 미리보기 주소에서 로그인이 안 된다)
- [ ] 포트원 심사 통과 후 등록할 도메인이 바뀌지 않는지 확인 (`inkword.site` 그대로라 문제없음)

## 4. 검증 (이전 직후 실행)

```bash
curl -sI https://inkword.site | head -3
curl -sL https://inkword.site | grep -c "외우지 마세요"
curl -sL https://inkword.site | grep -c "105동 603호"
curl -sL https://inkword.site/learning/index.html | grep -c "FREE_SCENES=3"
curl -sI https://inkword.site/learning/챕터1_완성동영상/scene-ch1-01.mp4 | head -3
curl -sI https://inkword.site | grep -i "server\|cf-ray"
```

| 항목 | 기대값 |
|---|---|
| 첫 줄 상태코드 | `200` |
| `외우지 마세요` | 1 이상 |
| `105동 603호` | 1 이상 |
| `FREE_SCENES=3` | 2 |
| 동영상 상태코드 | `200` (`content-type: video/mp4`) |
| `cf-ray` 헤더 | **존재해야 한다** — 클라우드플레어가 서빙 중이라는 증거 |

브라우저 확인:
- [ ] 로그인 정상
- [ ] 4번 콜로세움 → 잠금 안내창 → 결제창이 학습장 위에 뜸
- [ ] 동영상 재생

---

## 5. 금지

1. **`gh-pages` 브랜치를 지우지 마라.** 되돌릴 길이다. 최소 2주 유지
2. Cloudflare의 GitHub 자동 빌드 연동을 켜지 마라. `wrangler` 직접 업로드만 쓴다
3. 클라우드플레어가 읽어온 DNS 레코드를 **임의로 지우지 마라.** 메일이 죽는다
4. 소스 코드 수정 금지. 이번 작업은 호스팅 이전뿐이다
5. 유료 요금제 결제 금지. 무료로 충분하다

---

## 6. 되돌리기 — 문제가 생기면

구입처에서 **네임서버를 원래대로 되돌린다.** `gh-pages` 브랜치가 살아 있으므로 DNS가 퍼지는 대로 원상복구된다.
소요: 수십 분 ~ 수 시간(DNS 전파).

---

## 7. 같이 처리할 것 — 색

대표님이 **A / B / C** 중 고르시면, 호스팅 이전과 같은 날 반영한다.
시안: 아티팩트 `보는 단어장 — 색 시안 비교`

- **A안 — 먹 중심** (로부장 권고)
- B안 — 먹 + 초록 반반 (최소 수정)
- C안 — 먹 + 수채 주홍
