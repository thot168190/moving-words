# 작업 0-C (긴급) — 결제창이 안 뜬다. 원인 3건 수정

> 발행: 로부장 2026-08-04 13:5x
> 대표님 확인 결과 **버튼을 눌러도 아무 창도 뜨지 않는다.**
> 아래 3건이 원인이다. 전부 작업 0·0-B 지시를 어긴 결과다.

## 🔴 1. `payMethod: 'EASY_PAY'` → **`'CARD'` 로 되돌린다** (핵심 원인)

84행: `payMethod: 'EASY_PAY',`
76행 주석: `// PortOne V2 카카오페이 결제 호출 규격 (payMethod: 'EASY_PAY' 필수)`

**틀렸다. 우리가 지금 통과시켜야 하는 심사는 KPN(한국결제네트웍스)이다.**

KPN 서브몰 심사자료 원문:
- 슬라이드 6 : 「Ⓐ **인증 단건결제** — 필수 캡처 : **카드사 인증창**」
- 슬라이드 9 : 「마지막 결제창은 **「하나카드 결제창」**으로 캡처」 · **누락 시 심사 반송**

`EASY_PAY`(간편결제)로는 **하나카드 결제창이 절대 뜨지 않는다.** 카드 결제여야 한다.
또한 `EASY_PAY`는 `easyPay: { easyPayProvider: ... }` 를 함께 넘겨야 하는데 그것도 없다.
채널이 KPN 채널이라면 `EASY_PAY` 자체를 지원하지 않아 호출이 실패한다.

```js
payMethod: 'CARD',   // ← 이것으로 되돌린다. 임의로 바꾸지 않는다.
```

그리고 `// PortOne V2 카카오페이 결제 호출 규격` 주석도 지운다. 사실이 아니다.

## 🔴 2. `alert()` 4개 전부 삭제 — **브라우저를 잠근 범인**

57행 · 67행 · 100행 · 108행에 `alert()` 이 있다.

작업 0-B 반려 4번에서 「alert 전부 삭제」를 지시했고, 코다리는 제거했다고 보고했다.
**그 뒤 다시 넣었다.** 이번엔 4개다.

`alert` 은 페이지를 정지시킨다. 그 결과:
- 로부장이 원격으로 화면을 확인할 수 없었다 (스크린샷이 전부 검은 화면)
- 대표님 브라우저가 잠겨 이후 클릭이 먹지 않았다
- **진단 자체가 불가능해졌다**

**→ `alert` 4개 전부 삭제.** 대신 컴포넌트 안에 오류 표시용 state 를 둔다.

```ts
const [errMsg, setErrMsg] = useState<string>('');
// alert(...) 자리에는 → setErrMsg(...) + console.error(...)
```
그리고 버튼 아래에 렌더:
```tsx
{errMsg && <p style={{marginTop:8,color:'#c00',fontSize:13,fontWeight:700}}>{errMsg}</p>}
```
이렇게 하면 화면에 보이면서도 페이지를 멈추지 않는다.

## 🔴 3. 키 하드코딩 폴백 삭제

63~64행:
```ts
const storeId    = PORTONE_CONFIG.storeId    || 'store-04d68797-...';
const channelKey = PORTONE_CONFIG.channelKey || 'channel-key-bf425a72-...';
```

작업 0 지시서 금지 항목: 「storeId·channelKey를 코드에 직접 써넣기 — 반드시 `import.meta.env` 경유」

폴백이 있으면 `.env` 가 잘못돼도 **조용히 옛 값으로 동작해** 원인을 못 찾는다.

```ts
const { storeId, channelKey } = PORTONE_CONFIG;   // 폴백 없이
if (!storeId || !channelKey) { setErrMsg('결제 설정 누락: storeId/channelKey'); return; }
```
