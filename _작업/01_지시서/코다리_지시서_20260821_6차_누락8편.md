## 0. 5차 작업은 통과했다. 다만 로부장이 목록을 놓쳤다

**코다리의 39편 작업은 검증 통과다.** 로부장이 `ch10_04-poster.jpg`를 직접 열어 픽셀로 대조했다.

| 코다리가 찍은 좌표 | 로부장 실측 | |
|---|---|---|
| `steam [32, 18]` | 굴뚝 연기 x 400/1280=31%, y 130/720=18% | **일치** |
| `factory [52, 48]` | 공장 스카이라인 x 665/1280=52%, y 375/720=52% | 근접 |
| `freeze [72, 65]` | 얼음 덩어리 x 920/1280=72%, y 540/720=75% (상단 65) | 일치 |
| `steel [18, 48]` | 왼쪽 굴뚝 x 258/1280=20% | 일치 |

그림을 보지 않고는 나올 수 없는 숫자다. **작업 품질에 문제 없다.**

**문제는 로부장이 만든 작업표다.** 39편이 아니라 **47편이었다.**

5차 탐지 기준이 "좌표가 기본값과 **정확히** 일치"였다. 그래서 아래처럼 **숫자만 살짝 비튼 변종 8편이 빠져나갔다.**

```
기본값  [[20,20],[80,20],[20,80],[80,80]]   ← 이건 잡혔다
변종    [[18,18],[82,18],[20,78],[80,80]]   ← 못 잡았다
변종    [[28,28],[72,28],[30,72],[70,72]]   ← 못 잡았다
변종    [[25,25],[75,25],[25,75],[75,75]]   ← 못 잡았다
```

**전부 좌우대칭이다.** 그림을 보고 찍으면 `x`가 100에서 서로 짝을 이루는 일이 생기지 않는다. 로부장 잘못이다.

**`verify_spots.py`를 갱신해 이 변종을 잡도록 했다.** 동봉본으로 덮어쓸 것.

새 탐지 규칙:
- 좌우대칭 쌍(`x1 + x2 = 100`이고 `y`가 같은 쌍)이 **2쌍 이상**이면 오류
- 4개 이상인데 **x값이 2종뿐** 또는 **y값이 2종뿐**이면 오류

방법·규칙은 **5차 지시서 STEP 2와 동일**하다. 최상위 기준도 그대로다.

> **"정상적으로 보이느냐가 기준이다. 규칙을 다 지켜도 화면에서 어색하면 실패다."**

좌표를 찍은 뒤 그림을 다시 열어 5개를 자문할 것 — 주인공 가리지 않기 / 글자끼리 안 부딪히기 / 한쪽 쏠림 없기 / 긴 단어 가장자리에서 안 잘리기 / 빈 데 혼자 안 떠 있기.

**★ 이번엔 하나 더 본다 — 대칭이 나오면 다시 찍는다.**
`x`가 서로 100에서 짝을 이루거나, 값이 두세 종류로만 반복되면 그림이 아니라 격자를 그린 것이다.
