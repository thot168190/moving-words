## 1. 파일을 어디에 두는가

```
움직이는그림사전/_작업/프롬프트/
    ch01_INVENTIO/
    ch02_VITA/
        00_기준본.txt         ← 골격. 절대 수정 금지
        ch2-05_둥지.txt
        ch2-06_딱정벌레.txt
        ...
        99_판정.md            ← 통과/실패 기록
    ch03_DOMUS/
    ch04_SCHOLA/
```

**규칙 세 줄**

1. **한 편 = 한 파일.** 이름은 `ch2-05_둥지.txt` (챕터-편번호_소재)
2. **버전 번호를 파일명에 붙이지 않는다.** 고칠 때 같은 파일을 덮어쓴다.
   무엇을 왜 바꿨는지는 `99_판정.md`에 한 줄만 남긴다
3. **완성물은 반드시 저장소 안에 둔다.**
   `Desktop/코덱스/90_임시작업/`은 작업 중에만 쓰고, 끝나면 위 경로로 옮긴다.
   Desktop에 두면 git에 안 들어가고 사라진다

**금지** — `_to_delete/` 안의 파일은 절대 건드리지 않는다. 삭제도 하지 않는다.

## 2. 프롬프트를 어떻게 만드는가

### 2-1. 골격은 창작하지 않는다

`00_기준본.txt`의 문장을 **한 글자도 바꾸지 않는다.**
아래 5개 슬롯만 채운다.

| 슬롯 | 위치 | 내용 |
|---|---|---|
| A | 두 번째 문단 | 피사체 목록 |
| B | `0-4s:` 끝부분 | 그리는 순서 |
| C | 세 번째 문단 | 주인공 하나만 정밀하게 |
| D | `4-7s:` 중간 | 색 3종 |
| E | `7-8s:` 중간 | 사라지면 안 되는 것 재지정 |

나머지 문장은 전부 그대로 복사한다.

### 2-2. 오늘 피를 보고 얻은 금지사항 5개

**① 마지막에 동작을 넣지 않는다**
"풀이 미끄러져 들어간다" 같은 물리적 동작을 넣으면, Veo가 마지막 구간에서
화면을 다시 그리면서 **피사체를 하나씩 지운다.** 1차엔 새, 2차엔 알이 사라졌다.
`7-8s`는 반드시 "아무것도 움직이지 않고 아무것도 변하지 않는다"로 끝낸다.

**② `densely` `pressed close together` 같은 밀도 지시를 쓰지 않는다**
선이 촘촘해지면서 옅은 수채가 진한 연필 덩어리로 바뀐다.

**③ 긍정문(= `Never:` 앞)에 소환어를 쓰지 않는다**
막으려고 적은 단어가 오히려 불러온다. 실제 사고 사례:
- `hand` → 손이 화면에 나옴
- `pen` → 펜이 대문짝만하게 나옴
- `dark-charcoal` → 세필이 잉크 드로잉이 됨
- `narration` `voice` → **남성 영어 음성이 깔림**
- `for thoughtful young learners` → 유아용 그림체가 됨

차단은 전부 `Never:` 블록에서 한다. 부정문은 소환하지 않는다(검증됨).

**④ 주인공의 "디테일"과 "색 진하기"를 분리한다**
주인공을 정밀하게 그리라고 하면 색까지 진해진다.
선은 촘촘하게, 색은 다른 요소와 똑같이 옅게.

**⑤ 종(種) 특징이 색을 부른다**
`songbird`라고 쓰면 유럽울새(robin)로 그려서 주황 가슴이 나온다.
색을 억제하려 하지 말고 **애초에 그 색이 없는 소재를 고른다.**

## 3. 단어를 어떻게 고르는가

### 3-1. 절대 규칙

- **정본 1200 안에서만.** `_작업/all1200.txt`가 정본이다. 밖의 단어는 한 개도 안 된다
- **한 편 8단어.** 7개도 9개도 안 된다
- **레벨2 3개 이상.** `_작업/1200_레벨태그_v3.csv`로 확인한다
- **앞 4개 = 1단계, 뒤 4개 = 2단계**
- **화면에 실제로 그려진 것만.** 그림에 없는 추상어(`opinion` `regard` `freedom`)를 넣지 않는다

### 3-2. 순서를 거꾸로 한다

소재를 먼저 정하고 단어를 맞추면 **이미 쓴 단어가 또 나온다.**
실제로 VITA 초안에서 45슬롯 중 23개가 중복이었다.

**반드시 이 순서로 한다.**
1. `아직 안 쓴 단어 1,015개`에서 한 갈래를 고른다
2. 그 갈래에서 미사용 단어 8개를 뽑는다
3. **그 8개가 한 화면에 들어갈 장면**을 나중에 만든다

### 3-3. 단어는 창작하지 않는다

**대표님 승인 없이 단어를 만들거나 바꾸지 않는다.**
정본에 맞는 단어가 없으면 만들지 말고 **멈추고 보고한다.**

## 4. 제출 전 스스로 검사할 것

프롬프트를 넘기기 전에 아래를 직접 확인하고, 결과를 함께 보고한다.

```
[ ] 8단어인가
[ ] 전부 정본 1200 안인가
[ ] 레벨2가 3개 이상인가
[ ] 이미 쓴 단어와 겹치지 않는가
[ ] 8단어가 전부 화면에 그려지는가
[ ] Never: 앞에 hand/pen/pencil/brush/tool/paper/charcoal/narration/voice/
    children/figure/people 이 없는가
[ ] 7-8s가 "정지"로 끝나는가 (동작 없음)
[ ] densely / pressed close 같은 밀도 지시가 없는가
[ ] 골격 문장을 그대로 복사했는가
```

## 5. 하지 말 것

- 빌드 산출물(`dist/assets/*.js`, `*.css`) 직접 편집 — **사이트가 죽는다. 실제로 죽였다**
- `git commit` / `push` / 배포 — 로부장이 한다
- `.env` 열람·수정
- 결제 코드·약관·개인정보처리방침 수정
- 단어·문안·제목 창작
- 골격 문장 수정
- `_to_delete/` 안의 파일 삭제

**파일을 못 받았으면 만들지 말고 "못 받았다"고 멈춰서 보고한다.**
어제 이걸 안 지켜서 단어를 지어냈고, 대표님 검수본을 통째로 되돌려야 했다.
