### 번들 패치 2곳 (내용)

```
(1) 크롤 텍스트 인라인 스타일
    before: style:{whiteSpace:"pre",fontFamily:"Pretendard, sans-serif"}
    after : style:{whiteSpace:"pre",fontFamily:"Pretendard, sans-serif",
                   fontSize:"clamp(14px,3.6vw,64px)",
                   paddingLeft:"10px",paddingRight:"10px"}

(2) 크롤 시작 위치 단위
    before: transform:rotateX(22deg) translateY(95vh)
    after : transform:rotateX(22deg) translateY(95dvh)
```

**왜 이렇게 고쳤나 (코다리가 임의로 바꾸면 안 되는 이유)**

- 증상: 대표님 휴대폰에서 스타워즈 크롤 문구가 좌우로 잘리고 세로 위치가 안 맞음
- 원인 1 — 잘림: `whiteSpace:'pre'`라 자동 줄바꿈이 없는데 Tailwind `text-[26px]`가 고정폭이다.
  가장 긴 줄 "그려지는 과정을 볼 때 더 깊이 각인된다 —" 21자 × 26px ≈ 546px.
  iPhone 390px에서 `px-6`(좌우 24px) 빼면 가용 342px → **204px 초과 → 잘림.**
  `rotateX(22deg)` + `perspective:340px` 원근 때문에 아래쪽은 더 확대돼 잘림이 심해진다.
- 원인 2 — 세로 어긋남: 컨테이너는 `h-[100dvh]`인데 애니메이션 시작값만 `95vh`.
  모바일은 주소창 때문에 `vh > dvh` → 크롤이 화면 밖 더 아래에서 시작해 중앙 타이밍이 어긋난다.
- 해법: 인라인 `fontSize`는 Tailwind 클래스보다 우선순위가 높아 **CSS 재빌드 없이** 먹는다.
  `clamp(14px, 3.6vw, 64px)` 실측 검증:

| 화면폭 | 계산 폰트 | 21자 폭 | 가용폭(패딩 10px×2) | 판정 |
|---|---|---|---|---|
| 320px | 14px(하한) | 294px | 300px | ✅ |
| 353px | 14px(하한) | 294px | 333px | ✅ |
| 390px | 14.0px | 295px | 370px | ✅ |
| 430px | 15.5px | 325px | 410px | ✅ |
| 640px | 23.0px | 484px | 620px | ✅ |
| 1600px | 64px(상한) | 1344px | 1580px | ✅ |

## 코다리가 하지 말 것

- `npm run build` — 심사 중, 번들 해시가 바뀌면 검증 경로가 전부 깨진다
- 뜻 내용을 임의로 고치기 — 뜻 판정은 대표님만 한다
- `perspective:340px`이나 `rotateX(22deg)` 건드리기 — 이번엔 폰트·단위 2개만 바꿨다. **한 번에 하나씩** 원칙
- 크롤 섹션 자체를 제거하기 — 제거는 심사 통과 후 디자인 개편 때 대표님 판단으로 한다
