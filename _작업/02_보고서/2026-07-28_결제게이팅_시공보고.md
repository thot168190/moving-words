## 2. 고친 파일 5개

| 파일 | 무엇을 |
|---|---|
| `public/learning/index.html` | 결제 상태를 받아 4번째 장면부터 잠금. 잠금 클릭 시 부모 창에 알림 |
| `src/components/LearningPage.tsx` | 학습장에 `paid` 상태 전달. 잠금 클릭 시 `/#pricing` 으로 이동. 캐시 버전 갱신 |
| `src/contexts/AuthContext.tsx` | `isPaid` 상태 추가 (`profile.purchase` 존재 여부) |
| `src/lib/firestore.ts` | `UserProfile` 에 `purchase` 필드 정의 |
| `firestore.rules` | **클라이언트가 `purchase` 를 쓰지 못하게 차단** |

**마지막 줄이 핵심입니다.** 이게 없으면 사용자가 브라우저 콘솔에서 자기 문서에 `purchase` 를 넣어 결제를 우회할 수 있습니다.

## 4. ⚠️ 대표님이 직접 하셔야 하는 것 — 보안 규칙 적용

**`firestore.rules` 파일을 고쳤지만, 이건 배포해야 적용됩니다.** 파일만 고쳐서는 아무 효과가 없습니다.

**Firebase 콘솔에서 붙여넣기 (2분)**

1. Firebase 콘솔 → `moving-words-dictionary` → **Firestore Database** → **규칙** 탭
2. 현재 내용을 지우고, 프로젝트의 `firestore.rules` 파일 내용을 통째로 붙여넣기
3. **게시** 클릭

이걸 안 하면 **게이팅이 무의미합니다.** 사용자가 자기 문서에 `purchase` 를 직접 써넣으면 8장면이 다 열립니다.

## 5. 대표님이 확인하시는 법

배포 후 `inkword.site` 에 로그인하면 **4번째 장면부터 자물쇠**가 보여야 합니다. 눌러보시면 구매 안내가 뜨고 가격 섹션으로 이동합니다.

**8장면이 다 열리는지도 확인하시려면** — 아직 결제가 안 되니 수동으로 넣어야 합니다.

1. Firebase 콘솔 → Firestore Database → `users` 컬렉션
2. 본인 계정 문서 열기
3. 필드 추가: 이름 `purchase`, 유형 **map**
4. 그 안에 아무 하위 필드나 하나 넣기 (예: `orderId` = `test`)
5. 저장 후 학습장 새로고침 → **8장면 전부 열림**

확인 끝나면 그 필드를 지우시면 다시 잠깁니다.

⚠️ 단, **4번 보안 규칙을 먼저 적용하면 콘솔에서는 여전히 쓸 수 있지만 브라우저에서는 못 씁니다.** 콘솔은 관리자 권한이라 규칙을 우회합니다. 정상입니다.

## 6. 아직 안 된 것 — 결제 자체

**게이팅은 됐지만 결제는 아직 안 됩니다.**

지금 코드는 토스 SDK 직결이고, 테스트 키가 박혀 있고, 승인 서버가 없습니다. 포트원 심사가 끝나면 아래를 만듭니다.

| 순서 | 무엇 | 언제 |
|---|---|---|
| 1 | 포트원 SDK로 결제 버튼 교체 | 심사 중 미리 |
| 2 | 승인 조회 서버 (Vercel 함수 1개) | 심사 중 미리 |
| 3 | 승인 성공 시 `purchase` 기록 | 심사 중 미리 |
| 4 | 실제 키 꽂고 결제 테스트 | 승인 후 |

**심사 결과가 나오면 PG사별 상점아이디와 키를 주십시오.** 그러면 반나절이면 붙습니다.

## 7. 참고 — 이 게이팅의 한계

**클라이언트 게이팅입니다.** 영상 파일 주소를 직접 알아내면 브라우저에서 받을 수 있습니다.

지금 단계에서는 이게 맞습니다. 서버에서 영상마다 서명된 주소를 발급하는 구조는 며칠이 걸리고, 지금은 콘텐츠가 8장면뿐이라 그만한 공을 들일 때가 아닙니다.

**다만 알고는 계셔야 합니다.** 콘텐츠가 288편으로 늘고 매출이 붙으면 그때 서버 서명으로 올려야 합니다. 백로그에 적어 두겠습니다.
