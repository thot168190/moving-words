# 푸시 전 점검표

## 순서

```bash
bash _작업/푸시.sh "커밋 메시지"
```

이 하나면 dist 동기화 → 검증 → 커밋 → 푸시까지 순서대로 갑니다.
**검증에 걸리면 스스로 멈춥니다.** 걸린 채로 넘기지 마십시오.

## 로부장을 부를 자리

푸시 직전 한 번. 대화창에 이것만 붙이십시오.

```bash
python3 _작업/검증_전체.py
```

출력 **전체**를 자르지 말고 붙여주십시오. 그것만으로 판단합니다.

## 절대 하지 말 것

- `npm run build` — 심사 중입니다. 번들 해시가 바뀌면 검증 경로가 전부 깨집니다
- Netlify 배포
- `--no-history`
- 검증에 걸린 채로 푸시

## 푸시 뒤 눈으로 볼 것

1. 챕터1이 잠금 없이 열리는가
2. 챕터2에 소챕터 탭 세 개가 보이는가 — 전체 / 숲속 동물과 곤충 / 새와 나무와 씨앗
3. 탭을 누르면 목록이 실제로 바뀌는가
4. 챕터3 정원 편에서 단어가 그림의 제자리에 붙는가
5. 퀴즈를 눌러 단어를 끌어다 놓아지는가

하나라도 이상하면 되돌립니다.

```bash
git revert HEAD
git push origin $(git rev-parse --abbrev-ref HEAD)
```
