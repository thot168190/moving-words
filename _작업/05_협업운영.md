# 움직이는그림사전 — 3자 협업 운영 규칙

> 확정일: 2026-07-26  
> 목표: **2026년 8월 안에 출시**  
> 최종 결정권자: 대표님

---

## 1. 역할

| 담당 | 주 역할 | 책임 |
|---|---|---|
| 오퍼스(로부장) | 기획·상품·품질 검수 | 고객·상품 방향, 카피, 법적·사업 위험, 완료 결과의 독립 검수 |
| 안티그래비티 | 구현·화면 제작 | 코드 수정, 반응형 UI, 빌드, 기술 검증자료 제출 |
| 쏠(Codex) | 총괄·기록·출시관리 | 현황 원장 관리, 우선순위 조정, 시장조사, 작업 충돌 방지, 출시 체크리스트 관리 |
| 대표님 | 최종 승인 | 가격·상품·배포·외부 결제 계약·API 키 등 중요 결정 승인 |

### 기본 원칙

- 한 작업에는 **실행 담당자 1명**만 지정한다.
- 실행 담당자와 검수 담당자는 가능하면 다르게 둔다.
- 세 담당자는 작업 시작 전에 `_작업/00_현황.md`와 이 문서를 읽는다.
- 이전 작업자의 변경을 임의로 되돌리지 않는다.

---

## 2. 표준 작업 흐름

```text
대표님 목표·결정
  → 쏠: 작업번호·우선순위·완료기준 기록
  → 오퍼스: 기획·위험·카피 검토
  → 안티그래비티: 코드·화면 구현
  → 쏠: 결과 취합·누락·충돌 검사
  → 오퍼스: 독립 품질 검수
  → 대표님: 화면 확인·배포 승인
  → 지정된 1명만 배포
  → 쏠: 라이브 검증 및 현황 갱신
```

긴급 버그는 기획 단계를 줄일 수 있지만, 검증과 현황 기록은 생략하지 않는다.

---

## 3. 파일 소유와 기록 위치

| 자료 | 위치 | 작성 규칙 |
|---|---|---|
| 현재 상태·대표님 결정 | `_작업/00_현황.md` | 쏠이 단일 원장으로 관리 |
| 실행 지시 | `_작업/01_지시서/` | 작업번호·담당자·완료기준 필수 |
| 실행 결과 | `_작업/02_보고서/` | 수정 파일·검증 결과·남은 문제 기록 |
| 스크린샷·로그 | `_작업/03_증거/` | 원본을 날짜와 작업번호로 보관 |
| 출시 후 백로그 | `_작업/04_나중에.md` | 8월 출시 필수가 아닌 작업 |
| 협업 규칙 | `_작업/05_협업운영.md` | 역할 또는 절차 변경 시 갱신 |

`00_현황.md`만 현재 상태의 정본으로 사용한다. 보고서와 지시서가 현황과 충돌하면 대표님 결정과 `00_현황.md`를 우선한다.

---

## 4. 작업 인수인계 형식

모든 작업자는 종료 시 아래 6개 항목을 남긴다.

```text
[작업번호]
담당자:
완료한 것:
수정한 파일:
검증 결과:
남은 문제:
다음 담당자:
```

“완료”만 적지 않는다. 모바일 UI 작업은 390px 화면, 데스크톱은 1440px 화면을 확인한다. 결제 작업은 성공·실패·취소·중복요청을 확인한다.

---

## 5. 충돌 방지 규칙

1. 작업 시작 전 `git status`와 최근 보고서를 확인한다.
2. 같은 파일을 동시에 수정하지 않는다.
3. 실행 중인 작업은 `00_현황.md`에 담당자와 파일 범위를 표시한다.
4. 다른 담당자의 미완료 변경을 발견하면 삭제하거나 되돌리지 않고 보고한다.
5. 카피·가격·결제·법적 문구는 대표님 승인 없이 변경하지 않는다.
6. `.env`와 API 키는 문서·보고서·화면 캡처에 노출하지 않는다.

---

## 6. 배포 안전장치

기존 문서에 배포 주체가 서로 다르게 기록되어 있으므로, 새로 확정하기 전까지 아래 규칙을 적용한다.

- **대표님이 화면을 확인하고 “배포”라고 승인하기 전에는 배포 금지.**
- 승인 후에도 배포는 해당 작업에 지정된 **1명만** 실행한다.
- 배포 직전 현재 사이트와 배포 파일을 백업하거나 복구 가능한 상태인지 확인한다.
- 배포 후 PC·모바일에서 가입, 결제, 권한, 학습 화면을 확인한다.
- 장애가 있으면 새 수정부터 하지 말고 마지막 정상 버전으로 복구할 수 있는지 먼저 확인한다.

## 7. 8월 출시 판단 기준

### 출시 전 반드시 완료

- 모바일·PC 랜딩 정상 표시
- 회원가입·로그인
- 결제 성공·실패·취소 처리
- 결제자에게만 학습 권한 부여
- 최소 판매 콘텐츠와 판매 문구 일치
- 이용약관·개인정보·환불 안내
- 실제 도메인에서 전체 흐름 테스트

### 출시 후로 미룰 수 있음

- 고급 애니메이션과 장식
- 복잡한 통계 대시보드
- 다중 PG 자동 전환
- 해외 결제
- 관리자 기능의 세부 자동화
- 매출과 직접 관련 없는 디자인 개선

새 기능이 생기면 먼저 “8월 출시 필수인가?”를 판정한다. 필수가 아니면 `_작업/04_나중에.md`에 기록한다.
