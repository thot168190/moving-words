## 0. 이 문서를 읽는 AI에게 — 먼저 읽고 시작할 것

**판은 이미 확정돼 있다. 다시 짜지 마라.**

인계자(로부장)의 가장 큰 잘못은 확정된 설계를 스스로 의심하고 뒤집은 것이다.
대표님은 같은 결정을 세 번 네 번 다시 하셨고, 그때마다 작업이 멈췄다.

**지켜야 할 태도**
1. 아래 §1 「확정 사항」은 대표님이 이미 판정하신 것이다. 근거 없이 재검토하지 마라.
2. 문제를 발견하면 **판을 흔들지 말고, 그 자리만 고쳐라.**
3. 보고할 때는 **전수로 세고 나서** 보고하라. 물어보신 것만 검사하면 다음 질문 때 새 문제가 나오고, 대표님은 그걸 "말이 또 바뀐다"고 느끼신다. **실제로 그게 말이 바뀐 것이 맞다.**
4. 판정(합격/불합격, 구조 변경, 뜻 확정)은 **대표님만** 한다. AI는 선택지를 내지 말고 **사실과 숫자**를 내라.

## 1. 확정 사항 — 변경 금지

### 1-1. 제품
- 8초짜리 line-reveal(선이 스스로 그려지는) 영상 위에 영어 단어를 점으로 얹은 그림사전
- 무료: **챕터1, 챕터2**. 챕터3부터 유료
- 결제 심사(카카오페이/포트원) 진행 중 → **자리가 비어 보이면 안 된다**

### 1-2. 추상어 처리 방침 ★가장 중요
> **추상어는 그림에 직접 보이게 그리지 않는다. 장면에 스토리를 붙여서 푼다.**

이것이 원래 합의이고 확정 사항이다.
`district`를 「새집 구역」으로 푸는 것은 **설계대로 한 것이지 억지가 아니다.**

인계자는 2026-08-25에 이 방침을 "그림에 안 보이니 억지"라고 뒤집었다. **그 판단은 철회한다.**
다음 AI는 이 방침을 다시 의심하지 마라.

레벨 구분:
```
레벨1 (편당 4개 고정) : 그림에 눈으로 보이는 것
레벨2 (편당 4개)      : 같은 장면에서 스토리로 확장되는 말 (추상어가 여기 온다)
```
UI 문구도 "같은 장면에서 한 단계 깊은 어휘로 확장합니다"로 이미 그렇게 돼 있다.

### 1-3. 뜻 쓰는 규칙
- **뜻이 영어 단어보다 어려우면 안 된다** (한자어·음차 금지)
  - `marvel` = 경이(X) → 놀라운 것(O)
  - `comfort` = 위안(X) → 편안함(O)
- 뜻은 **단어의 본뜻**을 쓴다. 그림 설명을 뜻 자리에 넣지 마라.
  - `district` = 새집 구역(X) → 구역(O) ※그림은 예시일 뿐
- 뜻이 서로 겹치면 안 된다 (`joy`와 `delight`를 둘 다 「기쁨」으로 쓴 사고가 있었다)

### 1-4. 정본 골격 2계열 — 창작 금지, 슬롯만 채운다
```
WOW  (와)  _작업/01_지시서/프롬프트_공식_잠금.md §2   산호협곡 · 3막(0-3.5 / 3.5-5.5 / 5.5-8)
CALM (쉼)  _작업/성공문법_정본_line-reveal_20260809.md §1   망원경 · 2막(0-4 / 4-8)
```

### 1-5. 좌표 규칙
- x, y는 8~92 (가장자리 잘림 방지)
- 같은 레벨 안에서 서로 18 이상 떨어질 것
- **좌우대칭(x1+x2=100) 금지, 격자 금지** — 그림 안 보고 찍었다는 증거다
- 최종 기준(대표님 말): **"정상적으로 보이느냐가 기준이야"**

### 1-6. 절대 금지
- `npm run build` **금지** — 심사 중이라 번들 해시가 바뀌면 검증 경로가 다 깨진다.
  고칠 게 있으면 `dist/assets/index-*.js` 문자열을 직접 치환하고 해시명만 바꿔 캐시를 무효화한다.
- Netlify 배포 금지 · `--no-history` 금지
- 프롬프트를 대화창에 쓰지 마라. **복사 버튼이 있는 HTML**로 낸다
- 배포는 대표님 확인 뒤에

## 3. 남은 714개의 진짜 성격 — 대표님 질문에 대한 답

대표님 질문: *"처음부터 안 되는 일이었나? 남은 단어들이 뭔지, 상황 설명으로 안 되는 건지"*

**답: 안 되는 일이 아니다. 다만 지금 그리는 그림의 종류로는 안 된다.**

어느 챕터에도 배정 안 된 갈래 186개의 실제 내역:
```
사람과 관계  31개   citizen, community, crowd, neighbor, twin, female, male ...
돈           25개   coin, price, spend, earn, budget, tax, salary, debt ...
일의 결과    21개   cause, effect, result, succeed, purpose, happen ...
이음말       21개   despite, either, neither, nor, otherwise, thus, though ...
좋고 나쁨    15개   advantage, benefit, correct, fair, improve, perfect ...
묻고 부탁    13개   advice, beg, excuse, promise, request, suggest ...
사람 성격    12개   character, charm, gentle, polite, wise, smart ...
돕고 섬기기  11개   aid, assist, cure, forgive, serve, support ...
소리와 음악  10개   band, bang, concert, loud, noise, tone, whistle ...
바람과 아쉬움 9개   bore, desire, disappoint, hesitate, lack, pity ...
부끄러움/미움 7개   awkward, blame, embarrass, ignore, shame, silly ...
따지고 다투기 7개   argue, claim, complain, debate, deny, insist ...
운동과 겨루기 4개   champion, contest, golf, league
```

### 진단 — 이게 진짜 병목이다

**「돈」25개는 그림으로 된다.** 가게 계산대 장면 한 편이면 `coin` `price` `spend` `earn` `fee`가 한 화면에 다 들어간다. 아직 안 그렸을 뿐이다.

**「소리와 음악」10개도 된다.** ch9(음악)이 지금 0편이다. 악기 장면을 그리면 끝난다.

**「사람과 관계」31개, 「사람 성격」12개, 「부끄러움과 미움」7개, 「따지고 다투기」7개 — 이게 막힌 이유는 하나다.**
프롬프트 공식이 **"손이 나오면 안 된다"**에 묶여 있어서 **사람을 아예 못 그리게 돼 있다.**
`neighbor` `crowd` `argue` `embarrass`는 사람 없이는 그릴 수가 없다.
→ **손 금지 규칙은 "그리는 손"(연필 든 손)을 막으려던 것이지 "등장인물"을 막으려던 것이 아니다.** 이 둘을 분리하는 프롬프트 공식이 필요하다. **이것이 남은 작업 중 가장 값어치가 크다. (약 57개 단어가 여기 걸려 있다)**

**「이음말」21개(despite, either, neither, nor, otherwise, thus...)는 그림으로 안 된다.** 이건 문법어라 장면화 대상이 아니다.
→ 그림 매칭에서 빼고 **문장 카드/예문 형태의 별도 코너**로 처리해야 한다. 억지로 그림에 붙이지 마라.

### 요약
```
714개 중
  약 640개  → 된다. 장면 종류를 넓히면 된다 (가게·사람·음악·다툼 장면)
  약  74개  → 그림으로 안 된다 (이음말 21개 + 순수 문법어). 별도 코너로 뺀다
```
**"처음부터 안 되는 일"이 아니었다. 그릴 장면의 폭이 사물 정물에 갇혀 있었던 것이다.**

## 5. 프롬프트 지뢰 — 검증된 목록 (반드시 지킬 것)

이 단어들은 **부정문으로 써도** 그 물건을 소환한다. 모델이 부정어를 흘리고 명사만 가져간다.

| 쓰면 안 되는 말 | 나오는 것 |
|---|---|
| `hand` `pen` `pencil` `brush` `tool` (부정문 포함) | 손 |
| `never two hands` / `There are no ... drawing tools` | 손 |
| `draws itself` `by itself` | 손 |
| `spreading` | 붓·손·종이질감 |
| `whiteboard` | 흰 카드 액자 |
| `graphite` | 연필 든 손 + 힘없는 선 |
| `paper` `cream` `parchment` | 액자·종이질감 |
| `Never:` 목록 | **거기 적은 명사가 오히려 소환된다** |
| `for thoughtful young learners` | 유치한 톤 (챕터4 BAN 명시) |

**손을 막는 유일한 방법은 언급 자체를 없애고 요소를 한정하는 것이다:**
```
The only visible subjects throughout the sequence are {요소1}, {요소2}, {요소3}, {요소4}, {요소5}.
```

## 6. 데이터 구조

```js
chapterData[N] = { works[], levelOneWords[], levelTwoWords[], sceneSpots[], levelOneSpots[] }
```
- **5개 배열의 길이가 반드시 같아야 한다**
- `levelOneWords` → `levelOneSpots` / `levelTwoWords` → `sceneSpots` (짝이 어긋나기 쉬우니 주의)
- 퀴즈는 `levelOneWords[sceneIndex].slice(0,4)` → **레벨1은 4개 고정**
- `style="left:${spots[i][0]}%;top:${spots[i][1]}%"` → **좌표가 단어보다 적으면 그 편이 통째로 안 열린다**
- `scenes.json`은 **존재하지 않는다.** 모든 데이터는 `public/learning/index.html` 안의 `const chapterData = {` 에 있다

### 포스터는 반드시 마지막 프레임
line-reveal은 8초에 걸쳐 그려지므로 **첫 프레임은 빈 화면**이다. 포스터가 첫 프레임이면 매칭 작업자가 볼 게 없다.
```bash
ffmpeg -y -sseof -0.5 -i "$f" -vframes 1 -q:v 2 "${f%.mp4}-poster.jpg"
```

### 매칭 순서 — 거꾸로 하면 틀린다
```
(X) 챕터 정하기 → 그 챕터 단어에서 고르기
(O) 그림 보기 → 맞는 단어 찾기 → 챕터 정하기
```
`ch11_04`가 「우주와 과학」에 배정돼 있는데 실제 그림은 나무다리와 시냇물이었다. 위의 (X) 방식으로 한 결과다.

## 8. 인계자가 틀렸던 것 — 같은 실수 반복 방지용

다음 AI는 이 목록을 보고 **같은 함정을 피하라.** 대표님을 지치게 한 것은 작업량이 아니라 **말이 바뀐 것**이다.

| # | 틀린 것 | 원인 | 교훈 |
|---|---|---|---|
| 1 | 뜻 빈칸을 62개라 보고 → 실제 124칸 | 같은 단어가 `works`와 `levelWords`에 두 번 존재 | 전수로 세라 |
| 2 | `joy`와 `delight`를 둘 다 「기쁨」으로 | 검증 범위를 "내가 채운 것끼리"로 한정 | 전체와 대조하라 |
| 3 | 좌표 문제를 39편이라 보고 → 실제 47편 | 기본값과 **정확히** 일치하는 것만 탐지 | 변종을 잡는 규칙을 써라 |
| 4 | "좌표 다 고쳤다"고 보고했는데 안 고쳐짐 | 8/12 커밋은 「겹침」만 고쳤고 기본값 25편은 손도 안 댐 | 보고 전에 검증기를 돌려라 |
